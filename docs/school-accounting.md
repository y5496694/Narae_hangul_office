# 학교회계 품의 연결 (preview.23)

최근 preview.22의 지역별 업무포털·메신저·카카오 연결과 기존 나래4 v1 가중치를 유지한다. 이 변경은 학교회계 도구와 실행 절차의 추가이며 새 가중치 학습이 아니다.

나래4에 “학교회계 품의목록 조회해”, “품의 00007 상세 읽어줘”, “품의 예산 후보 조회해”, “품의 작성안 검산해”라고 요청한다. 작성안에는 제목·개요·요구일자·완료요구일자·예산명·품목의 수량과 단가를 제공한다. 없는 값은 질문으로 남기며 기존 문서의 값으로 채우지 않는다.

공통 CLI는 `narae-gyomu tool call edufine.requisition --args-file D:\Codex\tmp\품의요청.json`을 사용한다. 오피스 도구명은 `gyomu_edufine_requisition`이다. 자세한 인자와 공식 자료 링크는 동봉한 [학교회계 절차](../vendor/narae-gyomu/packages/narae_gyomoo_portal/skills/narae-gyomu-edufine/references/school-accounting.md)에 있다.

현재 구현: 목록·조건 입력 및 조회 버튼 실행, 문서번호/제목/연도에 묶인 상세 읽기, 예산 후보 읽기, 정수 원 단위 검산, 빈 신규 등록 화면 기본정보 네 항목의 미리보기·1회 입력·표시값 대조. 여러 열린 Nexacro MDI 창을 경로별로 구분한다. 반복 클릭 검사는 탭과 실제 컨트롤 ID를 구분하고 같은 버튼 반복 방지는 유지한다.

한계: 현재 렌더링된 행만 확인한다. query의 서버 조회 완료 시각·전체 건수·가상 스크롤 밖 행은 미확인이다. 예산 선택·품목 입력·첨부 업로드·저장·결재요청은 지원하지 않는다. 금융 품의 상신을 일반 WXS 공문 상신으로 대신하지 않는다. 재정기안 전체 실환경 합격이나 나래4 단독 실학교 완주로 설명하지 않는다.

검증: 실제 사업담당 목록, 기존 품의 상세 2건, 빈 등록 및 예산 후보를 읽기 전용으로 대조했다. 실제 저장·결재요청은 실행하지 않았다. 합성 Chrome 화면에서 목록→정확한 상세→조건 입력→빈 신규 기본정보 입력과 재입력 거절을 검증한다. 실제 학교 원본·사람 이름·세션 자료는 이 문서·공개 테스트·훈련자료에 포함하지 않는다.
