# 0.8.0 검증 결과

2026-10-28 · Windows 64비트 · 한컴오피스 2024 한글

- **OAuth·연결 검증 11/11:** 실제 로컬 콜백, PKCE·state·nonce, 서명된 ID 토큰 검증, DPAPI 저장·재시작, 계정 불일치 거절, 갱신 직렬화, 취소, 직접 사용 권한 구분, Responses SSE 완료·실패, Claude 도구/이미지 변환, 연결 방식별 키 보존.
- **실제 HWP/HWPX 작업:** 나래한글 엔진으로 문단과 2×2 표가 있는 합성 문서를 생성하고, 한글 2024에서 본문 교체·17pt 굵게 적용·현재 내용 재읽기·저장 후 재열기 통과. 편집하는 동안 같은 한글 앱을 사용함을 확인했다.
- **원문 보호:** 오래된 liveRevision 편집 요청을 거절했다. 파일 엔진은 미저장 변경이 있는 한글 파일을 덮어쓰지 않는다.
- **미리보기:** 두 형식 모두 실제 한글 PDF 1쪽 출력과 PNG 미리보기 통과. PDF 출력 중 원본 해시가 바뀌지 않았다.
- **앱 통합:** 기본 OAuth 설정을 확인하고 모의 OpenAI API로 읽기 → 본문/서식 편집 → 결과 확인의 3요청을 실제 UI와 한글에서 수행했다. 저장한 최신 PDF 미리보기를 화면으로 확인했다.
- **설치본 통합:** 한글과 공백을 포함하는 별도 설치 경로에서 전용 가상환경, Electron, 공식 Claude 로그인 CLI를 설치하고 같은 실제 UI/한글 편집 흐름을 통과했다.
- **엔진 원본 대조:** 나래한글 엔진의 Python 24개 파일을 기준 커밋과 AST로 비교했다. 설명 주석·docstring을 제외한 실행 코드는 일치한다. 원 저작권·MIT 허가문은 유지한다.
- **공개 파일 점검:** 앱/엔진 소스·설치 스크립트·문서만 배포한다. 사용자 문서·계정 토큰·API 키·대화·설치 글꼴·한컴 실행 파일은 포함하지 않는다.

검증 문서는 일회용 합성 파일이다. OAuth·AI 서버는 모의 서버를 사용했으며 실제 사용자 계정 승인이나 유료 요청을 보내지 않았다. 다른 PC의 한컴 보안 정책과 글꼴 구성까지 동일함을 보장하지 않는다.

재현 명령:

```powershell
npm test
node tests/native-smoke.cjs
node tests/app-smoke.cjs
```

네이티브 검증에는 Windows와 한컴오피스 2024가 필요하다. UI 통합 검증의 모델 서버는 로컬 모의 서버이며 외부 유료 API를 호출하지 않는다.
